# 난이도·안내·소리·Windows 품질 개선

2026-10-02, Windows 0.10.0 개발 빌드 / 플레이 규칙 식별자 `quality-1`.

이 문서의 밸런스 수치는 이전 바닥형 얼음 규칙의 기록이다. 이후 `frozen-2`에서 얼음 속 캔디의 교환·낙하·셔플을 막고 타격 시 얼음만 한 겹 깨지도록 변경했다. 현재 검사 결과는 [testing.md](testing.md)와 `Builds/Validation/frozen/`을 참고한다. 서로 다른 규칙의 플레이 기록은 같은 성공률로 합치지 않는다.

## 난이도와 아이템

동일 초기 보드와 보충 seed를 사용한 3,456회 자동 비교를 실행했다. 일반 스테이지는 조건별 24회, 5-6·5-9는 조건별 96회다. 보충 seed 3개에 탐색 가중치·선택 변형을 조합하므로 독립적인 사람 96명의 결과나 사람 성공률로 해석하지 않는다.

| 스테이지 | 이동 | 아이템 없이 성공 | 아이템 최대 2개 성공 | 평균 사용량 |
| --- | ---: | ---: | ---: | ---: |
| 5-6 이전 | 29 | 64/96 (66.7%) | 90/96 (93.8%) | 0.802 |
| 5-6 적용 | 31 | 73/96 (76.0%) | 90/96 (93.8%) | 0.542 |
| 5-9 이전 | 29 | 58/96 (60.4%) | 87/96 (90.6%) | 0.833 |
| 5-9 적용 | 31 | 68/96 (70.8%) | 92/96 (95.8%) | 0.698 |

5-6·5-9의 이동만 29→31로 변경했다. 다른 레벨, 아이템 효과·초기 지급·보상량은 유지했다. `FeatureSetup`에서 다시 만들어도 같은 이동수가 나온다. [전체 원시 결과](balance-items-before-quality-1.csv)의 `current`는 조정 전, `moves+2`는 적용한 값, `moves+4`는 채택하지 않은 비교 조건이다.

아이템 정책은 남은 4회부터 얼음이 있으면 폭탄, 2회 이하면 망치, 마지막 1회에서 이동 +5를 우선 고려하고, 한 시도에 최대 2개/종류별 1개만 쓴다. 셔플은 이 봇의 선택 정책에 포함하지 않았다. 따라서 수치로 셔플의 가치나 캠페인 전체의 재고 부족을 판단할 수 없다. 셔플의 규칙·재고·반복 사용은 별도 실행 검사 대상이다. `BalanceAudit.Run`을 다시 실행하면 그 시점의 레벨 이동수를 기준으로 비교하므로 이 이전 결과 파일을 구분해 보관한다.

### 실제 플레이 집계

- 기록은 사용자 저장 폴더의 `playtest.jsonl`에만 남는다. 외부로 보내지 않는다.
- 시도 ID, 출처(`player`, `automated`, `editor`), 규칙 버전, 사용 아이템 종류, 이동·남은 이동, 플레이 시간, 결과와 실패 의견을 기록한다.
- Unity 메뉴 `Puzzle Game > Analyze Playtest Log`에서 파일을 선택하면 `Builds/Reports/Playtest/stages.csv`와 설명 파일을 만든다.
- 출처/규칙 버전/스테이지/아이템 사용 유무별로 구분한다. `finished_win_rate = 승리 / (승리 + 패배)`이며 중도 재시작·맵 이탈은 `abandoned`에 따로 표시한다. 평균 아이템과 시간은 중도 이탈도 포함한다.
- 피드백은 시도 ID로 연결하며 중복 시도와 P 키 클리어는 성공률에서 제외한다. 예전 기록은 `legacy`로 분리하며 사람 기록이라고 가정하지 않는다. 손상된 줄·잘못된 레벨·비정상 수치는 건너뛰고 개수를 표시한다.
- 이번 개선 시점에는 실제 사용자 기록이 없어 사람의 성공률을 산출하지 않았다. 자동 기록을 사람 기록으로 대신하지 않는다.

## 안내와 접근성

설정 > 소리 / 언어 / 접근성 > 기타 > 그림으로 보는 도움말에서 기본/특수 캔디/얼음/아이템 4페이지를 볼 수 있다. 각 페이지는 게임에 쓰인 입체 그림을 사용하며 맵과 스테이지 모두에서 열 수 있다. 고정 제목·하단 뒤로 가기와 탭을 포함한 스크롤 본문을 사용한다.

첫 5개 스테이지 안내는 주제와 연결했다. 1번은 유효 이동 1회, 2번은 2회, 3번은 줄무늬 생성, 4번은 포장/무지개 생성, 5번은 얼음 피해를 실제로 본 뒤 사라진다. 사용자가 직접 닫을 수도 있고 재시작하면 다시 표시한다.

언어/효과 설정의 **캔디 숫자 표시**는 기본 꺼짐이며 저장된다. 사탕의 색을 1~6으로 표시하고 같은 숫자를 수집 목표에도 표시한다. 입체 캔디·얼음 그림은 유지한다. 아이템 슬롯은 짧은 이름과 더 큰 최소 글자 크기를 사용한다.

## 소리

자체 합성곡을 48초에서 144초로 늘리고 세 구간의 음형·휴지·반주 밀도를 바꿨다. 효과음은 최대 3개, 같은 소리는 0.12초 이내 중복 재생을 막는다. 클리어/실패/완주는 기존 효과음을 정리한 뒤 우선 재생하고 그동안 게임 효과음을 억제한다. 특수 발동과 결과음에서는 배경음이 잠시 낮아진다. 모두 실제 시간 기준이므로 설정에서 일시정지한 상태에서도 효과음 미리듣기가 된다.

음악 파형 peak 상한 0.14, 효과음 0.23으로 제한해 최대 음량에서도 3개 효과음+음악의 합산 여유를 둔다. 이 수치는 청취 품질이나 장시간 반복감 평가를 대체하지 않는다.

## 재현 도구

- `Puzzle Game > Prepare Quality Improvements`: 레벨 재생성 없이 안내 그림·숫자 표식·글리프 연결.
- `Puzzle Game > Audit Item Balance`: 현재 레벨 데이터의 자동 비교 CSV.
- `QualitySmokeCheck`: 개발 빌드에서만 포함되는 별도 저장 경로 기반 반복 검사. `-puzzleQualitySmokeTest`, `-puzzleProgressPath`, `-puzzleSettingsPath`, `-puzzleSmokeReport`, `-puzzleWinningRoutes`, `-puzzleCaptureFolder` 사용. 반복량은 `-puzzleStressCycles`, 최소 시간은 `-puzzleStressSeconds`로 지정한다.
- 독립 재실행은 `-puzzleQualityReloadTest`와 같은 저장 경로를 사용한다.
- `stability.csv`는 10회 주기로 GC 후 관리 메모리/Unity 할당/오브젝트 수와 게임 구간 프레임 p95·최대를 기록한다. 씬 로딩·의도적 리소스 정리 시간은 프레임 표본에서 제외한다. 10회 준비 후 관리 메모리 +32 MB/Unity +96 MB를 실패 상한으로 둔다. 자동화는 숨긴 창으로 실행하므로 이 프레임 값은 활성 창의 GPU 성능이나 실제 플레이 FPS로 환산하지 않는다. 화면 검수는 별도의 960×600/800×1000 렌더 출력으로 진행한다.

최종 Windows 검사에서 601초/264회 반복, 맵 전환 528회·재시작 528회·아이템 사용 264회를 통과했다. 별도 프로세스에서도 저장된 설정과 재고가 복원됐다. 프로젝트 검사 157개가 통과했다. 실제 측정의 범위·수치와 남은 사람 검증은 [testing.md](testing.md)에 기록한다. 10분 내외 자동 반복 검사는 수 시간 플레이나 다른 PC의 드라이버·배율·소리 환경 검증과 별개다.
