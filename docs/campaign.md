# 50개 스테이지와 로컬 진행 저장

## 별·메달과 UI 확장 — 저장 v4 (0.11.0)

정상 클리어는 별 1개, 한 판에서 아이템을 사용하지 않으면 1개, 기본 이동의 20% 이상(올림, 최소 3회)을 남기면 1개를 받는다. 여유 이동은 `시작 이동 - 실제 사용 이동`으로 계산하므로 이동 +5의 남은 횟수는 평가를 올리지 않는다. 아이템의 대상 선택·취소·중단 환불은 사용으로 계산하지 않으며 효과가 완료된 사용만 센다. P 클리어는 진행 해금을 유지하되 새 별·메달·아이템 보상을 주지 않는다.

레벨별 별은 한 번의 플레이에서 얻은 최고 개수이며, 아이템 없이/여유 이동 메달은 별도로 누적한다. v4는 기존 완료·최고 점수·선택·아이템·보상 배열에 `stars`, `cleanMedals`, `efficientMedals`를 추가한다. v2/v3는 레벨 번호 1~50의 대응과 기존 기록·재고를 유지하고 완료 기록에 별 1개를 부여한다. v1의 100개 스테이지는 기존의 월드별 앞 10개 유지 규칙으로 이전한다. 아이템이 없던 v1/v2에는 시작 재고를 지급하며 과거 메달은 추정하지 않는다.

지도는 별, 월드 진행, 다음 5의 배수 스테이지 보상과 새 경로 안내를 보여 준다. 잠긴 노드도 목표와 이전 스테이지 해금 조건을 볼 수 있지만 시작할 수 없다. 입장창에 첫 보상의 종류·수령 여부, 별 조건과 메달 상태를 표시한다. 결과창은 목표별 부족량, 최고 기록 갱신, 별·메달과 실제 지급된 보상 그림을 표시한다.

조작은 기존 드래그/클릭에 방향키 커서와 Enter 선택/교환을 추가했다. 1~4는 아이템 설명을 열고, 별도의 사용 확인 후 대상을 선택한다. H는 수동 힌트, F1은 도움말이다. Esc는 팝업/선택을 먼저 취소하고 설정을 연다. 진행 중 맵 이동이나 재시작은 확인 후 수행하며, 이미 완료한 아이템 사용은 환불되지 않는다.

화면/소리/플레이/도움말을 같은 설정창에서 다룬다. 자동 힌트 사용 여부와 3/6/10/15초 대기, 보드 연출 1/1.5/2배는 `settings.json`에 저장한다. 배속은 이동 횟수·게임 규칙·실제 플레이 기록 시간과 분리하며, 설정 중에는 보드가 멈춘다. 추천 힌트는 현재 첫 제거 결과의 미완료 목표·얼음·특수 생성을 평가하며 미래 보충 캔디를 미리 보지 않는다.

## 소비형 아이템 — 저장 v3 (2026-10-02)

현재 얼음 규칙은 `frozen-2`다. 얼음이 남은 캔디는 교환·낙하·셔플로 움직이지 않는다. 같은 색 매치·특수·아이템 타격은 한 겹에 흡수되며 캔디가 남는다. 마지막 겹이 깨지면 해당 캔디가 풀려나고 얼음 목표가 오른다. 얼음만 깨진 타격은 점수·색상 수집을 올리지 않는다. 얼어 있는 특수 캔디는 다음 해동 후 타격부터 발동한다.

얼음 아래 막힌 공간은 구간 안에서 낙하하고, 비어 있는 칸에는 새 캔디가 직접 나타난다. 모든 칸이 얼어 있는 매치는 연쇄로 스스로 반복해서 깨지지 않는다. 셔플은 얼지 않은 칸만 바꾸며, 턴 종료 시 유효 교환도 자동 재배치도 불가능하면 막힘 사유를 표시하고 종료한다.

| 아이템 | 사용 방식 | 효과 |
| --- | --- | --- |
| 캔디 망치 | 설명창에서 대상 선택 후 캔디 클릭 | 한 칸 타격. 얼음이 있으면 한 겹만 깨고 캔디 유지, 없으면 캔디 제거·기존 특수 발동 |
| 캔디 폭탄 | 설명창에서 대상 선택 후 캔디 클릭 | 중심 포함 3×3 타격, 가장자리에서 범위 제한. 얼음은 한 겹씩 피해를 흡수하며 얼지 않은 특수 캔디만 발동 |
| 전체 섞기 | 설명창에서 1개 사용 | 얼지 않은 캔디만 재배치. 얼음 속 캔디의 위치·ID·색·특수 종류 유지. 가능한 배치를 찾지 못하면 차감 없이 안내 |
| 이동 +5 | 설명창에서 1개 사용 | 이번 시도의 남은 이동 +5, 이미 끝난 스테이지에는 사용 불가 |

- 처음에는 각 3개, 종류별 최대 99개다. 스테이지 첫 정상 클리어에 `(스테이지 번호 - 1) % 4` 순서의 아이템 1개를 받는다. 5의 배수 스테이지는 대신 각 종류 1개를 받는다. 상한에 도달한 종류의 초과분은 적립되지 않는다.
- 완료 기록과 별도의 `itemRewardsClaimed[50]`으로 중복을 차단한다. 재도전 보상은 없으며 P 이스터에그는 보상을 주지 않는다. P로 완료한 스테이지도 나중에 정상 클리어하면 첫 보상을 받을 수 있다.
- 모든 아이템은 이동수를 사용하지 않는다. 보드 처리·일시정지·결과 표시 중 사용과 0개 재고 사용을 막는다. 설명창에서 진행을 일시정지한다. 대상 선택 중 같은 슬롯·Esc·우클릭·닫기는 무료 취소이며, 설정을 열거나 포커스를 잃어도 취소한다.
- 사용 직전에 재고를 저장한다. 저장 실패 시 수량을 복구하고 효과를 시작하지 않는다. 진행 중 효과를 재시작/비활성화/P로 중단하면 보드·점수·수집·얼음을 되돌리고 아이템을 환불한다. 처리가 끝난 사용은 실패/재도전해도 반환하지 않는다. 보드와 남은 이동은 다음 실행에 이어서 저장하지 않는다.
- 아이템 도입 당시 v1/v2를 v3로 이전했으며, 현재는 위의 v4 이전까지 이어서 처리한다. 이전 저장에는 시작 재고와 미수령 보상 플래그를 부여한다. 따라서 이전에 깬 스테이지도 업데이트 후 첫 정상 클리어 보상을 한 번 받을 수 있다. 진행 초기화는 아이템·보상 플래그·별·메달도 초기화한다.
- `playtest.jsonl`에 `item,종류,x,y` 사용 순서와 `bonusMoves`를 기록한다. `moves`는 추가 이동을 제외한 실제 교환 횟수다. 취소된 아이템 사용은 기록하지 않는다.
- 아트/씬 재등록은 `Puzzle Game > Prepare Item Inventory`를 실행한다. 레벨 데이터는 변경하지 않는다.

## 저장

게임 설치 파일이 들어 있는 `practice_puzzle_game_Data`는 배포 데이터다. 사용자 진행은 **`Application.persistentDataPath/progress.json`**으로 분리한다. 업데이트로 게임 폴더를 교체해도 별도 사용자 저장을 이어서 읽는다. [Unity API 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Application-persistentDataPath.html).

현재 프로젝트 설정은 `DefaultCompany / practice_puzzle_game`이다.

- Windows: `%USERPROFILE%/AppData/LocalLow/DefaultCompany/practice_puzzle_game/progress.json`
- macOS: Unity가 정한 `Application Support` 아래 사용자 저장 경로. 코드는 OS 경로를 직접 조합하지 않는다. Mac 실기기 확인은 대기다.

저장 내용은 형식 버전, 고정 번호 1~50의 클리어 여부, 최고 점수, 마지막 선택 번호다. 이 번호와 ID의 대응은 유지해야 하며 재정렬/콘텐츠 추가는 저장 버전과 마이그레이션을 함께 설계한다. Company Name/Product Name을 출시 때 바꾸면 기존 경로의 이전 처리가 필요하다.

현재 저장 형식은 v2다. 이전 v1(월드당 20개, 총 100개) 파일은 자동으로 읽어 각 월드의 1~10 클리어와 최고 점수를 보존한다. 제거한 11~20을 선택했던 경우 새 구성의 다음 도전 위치로 옮긴다. 예를 들어 기존 2-5까지 완료했다면 새 구성에서는 1월드 10개와 2월드 5개의 완료가 유지된다. 변환된 진행은 다음 선택/클리어 저장 때 v2로 기록하며 이전 파일은 백업에 남는다.

클리어 직후와 스테이지 선택 시 저장한다. 종료 이벤트만 기다리지 않는다. `.tmp`에 먼저 쓰고 원본을 교체하며 이전 저장을 `.bak`에 둔다. 시작할 때 본 파일의 형식·배열·순차 해금 조건을 검사하고 손상이 있으면 백업을 읽는다. 둘 다 없거나 잘못되면 1-1부터 시작한다. 쓰기 실패는 결과창에 알리고 메모리 내 진행은 유지한다. 최고 점수는 재도전에서 낮아지지 않는다.

현재는 기기 내 단일 사용자 기록이다. 계정 로그인·서버 저장·다른 PC/Mac으로 자동 동기화하지 않는다. 진행 중 보드·사용한 이동수도 저장 대상이 아니다. 향후 로그인 로더가 계정 데이터를 받으면 `CampaignProgress` 로드 단계와 연결하면 된다.

Editor 플레이는 매 실행마다 메모리 진행도로 시작해 개인 저장을 건드리지 않는다. 개발 빌드/Editor에서만 `-puzzleProgressPath <격리된 JSON 파일>`로 경로를 지정할 수 있다. 일반 플레이어는 위 사용자 경로를 사용한다.

## 0.10.0 Frost와 난이도 조정 (2026-10-02)

1~4번의 점수 목표는 500/600/750/850점, 이동수는 20회다. 2번부터 색상 수집을 안내하고 5번에서 Frost 3칸을 도입한다. 첫 5개 레벨은 초기 64개 색을 데이터로 보관한다. 현재 `frozen-2`에서는 얼음을 모두 깨기 전까지 안의 캔디가 고정된다. 이전 바닥형 규칙의 첫 교환 예제는 적용하지 않는다.

6번 이후에는 월드와 스테이지에 따라 6~17개의 Frost를 배치한다. 3월드부터 일부 칸은 내구도 2를 갖는다. 장애물 목표는 배치의 약 70%이며 점수·색상 목표도 함께 만족해야 한다. 5번 이후 월드별 이동수는 26/24/28/27/29회다. 수집 목표와 얼음 내구도가 바뀌므로 점수/이동수 비율 하나로 난이도를 판단하지 않는다.

`CampaignValidation.Run`은 실제 Core 제거·특수·보충·셔플 규칙으로 기본 보충 seed 16개 전략, 두 추가 보충 seed 각 8개 전략을 실행한다. 총 1,600회이며 모든 레벨/난수 조건에서 클리어 경로를 찾았다. 원래 초기 배치는 유지하고 보충·셔플 난수만 바꿔 운에 따른 차이를 확인한다. 실제 게임은 저장한 기본 seed를 사용한다.
