# 50개 스테이지와 로컬 진행 저장

2026-10-01 / 0.9.4

## 화면 흐름

`Boot(현재 약 5초) → WorldMap → 선택한 Game → 결과/다음 스테이지/WorldMap`

처음에는 1-1만 열려 있다. 1-1을 클리어하면 1-2, 1-10을 클리어하면 2-1이 열린다. 완료한 스테이지는 재도전할 수 있다. 마지막 5-10은 다음 버튼을 숨긴다. 로드맵에서는 다른 월드의 배경과 잠긴 노드를 미리 볼 수 있지만 입장은 해금 조건을 검사한다. 설정 버튼과 ESC는 로드맵과 게임 모두에서 동작한다.

지도는 월드별 전용 미니어처 일러스트를 사용한다. 0.9.4에서 사용자가 선택한 보석 버튼 3종을 크림 길 위에 64×64 크기로 배치했다. 숫자는 Bagel Fat One의 둥근 글꼴로 1~10만 표시한다. 보석의 두꺼운 아래 테두리를 제외한 윗면 중심에 맞추며, 글꼴의 줄 높이 대신 실제 글자 모양을 기준으로 가로·세로 중앙 정렬한다. 클릭 영역은 106×76을 유지한다. 게임 HUD와 저장에는 1-1~5-10 식별을 유지한다. 완료는 초록색, 도전 가능은 분홍색, 잠금은 연보라색이다. 현재 위치 안내와 맥동하는 빛, 작은 설탕 반짝임이 움직인다. 지도와 표식은 같은 1280×800 좌표계에서 비율을 유지해 창 비율이 달라져도 어긋나지 않는다. 남는 화면은 같은 테마의 주변 풍경으로 채운다.

## 월드와 난이도

| 월드 | 범위 | 테마 | 이동수 | 수집 목표 |
| --- | --- | --- | --- | --- |
| 1 | 1-1~1-10 | 사탕 정원 | 20 | 1-5까지 점수만, 이후 1색 |
| 2 | 2-1~2-10 | 오렌지 과수원 | 20 | 1색 |
| 3 | 3-1~3-10 | 얼음 소다 | 19 | 2색 |
| 4 | 4-1~4-10 | 포도 밤정원 | 19 | 2색 |
| 5 | 5-1~5-10 | 무지개 궁전 | 18 | 3색 |

모두 8×8·6색 보드다. 서로 다른 seed의 50개 초기 배치를 제공하며 초기 매치가 없고 가능한 이동이 존재한다. 점수는 1,000부터 스테이지당 10씩 높여 마지막 목표는 1,490점이다. 수집 목표는 1월드에서 11~13개, 이후 14~23개로 증가하며 대상 색은 레벨마다 바뀐다. 점수와 모든 색상 목표를 함께 달성해야 한다. 실제 제거된 캔디만 수집하며 새로 만들어져 살아남은 특수 캔디는 수집하지 않는다.

`CampaignValidation`은 실제 Core 규칙·보충 난수·특수 효과·셔플로 전략별 플레이를 수행한다. 50개 모두 이기는 입력 경로를 찾았지만 이는 사람이 느끼는 난이도나 일정한 승률을 보장하지 않는다. 후반 맵은 실제 플레이 결과를 보고 더 조절해야 한다. 장애물·보드 모양 변형·튜토리얼은 후속 작업이다.

## 저장

게임 설치 파일이 들어 있는 `practice_puzzle_game_Data`는 배포 데이터다. 사용자 진행은 **`Application.persistentDataPath/progress.json`**으로 분리한다. 업데이트로 게임 폴더를 교체해도 별도 사용자 저장을 이어서 읽는다. [Unity API 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Application-persistentDataPath.html).

현재 프로젝트 설정은 `DefaultCompany / practice_puzzle_game`이다.

- Windows: `%USERPROFILE%/AppData/LocalLow/DefaultCompany/practice_puzzle_game/progress.json`
- macOS: Unity가 정한 `Application Support` 아래 사용자 저장 경로. 코드는 OS 경로를 직접 조합하지 않는다. Mac 실기기 확인은 대기다.

저장 내용은 형식 버전, 고정 번호 1~50의 클리어 여부, 최고 점수, 마지막 선택 번호다. 이 번호와 ID의 대응은 유지해야 하며 재정렬/콘텐츠 추가는 저장 버전과 마이그레이션을 함께 설계한다. Company Name/Product Name을 출시 때 바꾸면 기존 경로의 이전 처리가 필요하다.

현재 저장 형식은 v2다. 이전 v1(월드당 20개, 총 100개) 파일은 자동으로 읽어 각 월드의 1~10 클리어와 최고 점수를 보존한다. 제거한 11~20을 선택했던 경우 새 구성의 다음 도전 위치로 옮긴다. 예를 들어 기존 2-5까지 완료했다면 새 구성에서는 1월드 10개와 2월드 5개의 완료가 유지된다. 변환된 진행은 다음 선택/클리어 저장 때 v2로 기록하며 이전 파일은 백업에 남는다.

클리어 직후와 스테이지 선택 시 저장한다. 종료 이벤트만 기다리지 않는다. `.tmp`에 먼저 쓰고 원본을 교체하며 이전 저장을 `.bak`에 둔다. 시작할 때 본 파일의 형식·배열·순차 해금 조건을 검사하고 손상이 있으면 백업을 읽는다. 둘 다 없거나 잘못되면 1-1부터 시작한다. 쓰기 실패는 결과창에 알리고 메모리 내 진행은 유지한다. 최고 점수는 재도전에서 낮아지지 않는다.

현재는 기기 내 단일 사용자 기록이다. 계정 로그인·서버 저장·다른 PC/Mac으로 자동 동기화하지 않는다. 진행 중 보드·사용한 이동수도 저장 대상이 아니다. 향후 로그인 로더가 계정 데이터를 받으면 `CampaignProgress` 로드 단계와 연결하면 된다.

Editor 플레이는 매 실행마다 메모리 진행도로 시작해 개인 저장을 건드리지 않는다. 개발 빌드/Editor에서만 `-puzzleProgressPath <격리된 JSON 파일>`로 경로를 지정할 수 있다. 일반 플레이어는 위 사용자 경로를 사용한다.

## 제작과 검증

- `Level_001.asset`~`Level_050.asset`: ID·표시 이름·seed·점수·이동수·색별 수집 수량. Inspector에서 개별 조정.
- `LevelCatalog.asset`: 레벨 50개와 월드별 이름·배경 Sprite·재질 참조.
- **Puzzle Game / Prepare 50 Stage Campaign**: 현재 기본 공식을 사용해 레벨/씬을 다시 생성한다. 개별 수동 조정도 덮어쓰므로 일반 실행/빌드에는 필요 없다.
- **Puzzle Game / Validate Campaign Routes**: 현재 제작 데이터를 변경하지 않고 검사한다. CSV와 재현 입력 경로는 `Builds/Validation/campaign`에 출력한다.
- **Puzzle Game / Rebuild Illustrated World Map**: 레벨 데이터와 저장 형식은 유지하면서 지도 씬·지도 아트 참조만 다시 생성한다.
- **Puzzle Game / Build Windows Prototype**: Boot, WorldMap, Game을 묶어 0.9.4 개발 빌드를 만든다.
